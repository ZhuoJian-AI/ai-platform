### HIGH

**H1 分享链接必 410**
`frontend/src/pages/terminal/BrowserDrawer.tsx:585` 拼 `/api/v1/terminal/public/files/{id}`，该路由在 `llm_router/backend/app/api/terminal.py:1420` 已被改成无条件 `raise 410`。触发：终端里打开 agent 生成的 HTML/doc → 点「生成分享链接」。用户看到「已复制」，收件人打开是 410；发出去才知道坏了。修：改调 `terminal.createWsShare()`（`WorkspaceManagerView.tsx:451` 已是对的）。相关 e1be902。

**H2 工具结果被截到 4000 字喂给模型**
`llm_router/backend/app/api/dsh_internal.py:289` 把完整结果绑到 `_message` 丢弃，只把 `nodes.py:1987` 的 4000 字 preview 当 tool-result 回给模型；`paginate_file_content` 的 `content` 排在 `has_more/next_offset` 之后，模型看到「还有下一页」但正文被腰斩，按 next_offset 续读会永久跳过中间内容。触发：读任何 >4KB 的文件、列文件较多的空间、长 skill 输出。现象：AI「读了文件」却只答前几十行。修：返回 `_message["content"]`。相关 8be6543（仓库自带的 `test_agent_file_references.py:109` 断言的正是被违反的契约）。

**H3 编辑个人长期记忆 500**
`llm_router/backend/app/api/memory.py:92` 的 `model_copy(update={"scope_type": None,...})` 会把这两个键加进 fields_set，`memory_service.py:340` 的 `exclude_unset` 于是把 NULL 写进 `NOT NULL` 列（`models/memory.py:30`）。触发：管理员改某个用户节点的记忆。现象：只有个人记忆保存报错，组织/部门/团队正常。修：改成剔除键而非置 None。

**H4 句子里出现「是否」就禁用全部文件工具**
`workspace_permission_service.py:211` 把「能不能/能否/是否/可不可以」判定为权限提问，`nodes.py:422` 据此对**所有**文件工具（含写个人空间，nodes.py:481/520/615/694/711/734/749/763/1737）直接返回「权限问题只能依据权限摘要回答」。触发：上传 xlsx 后问「检查**是否**有重复行并生成去重表」。现象：每次调用都报权限错误，文件根本没被读。修：把该守卫限制在只读共享空间路径，并删掉「是否」这个词。相关 7df310a/4a3dcc5。

**H5 知识库删掉的文档还能被检索到**
`rag_service.py:597` 明确不级联删 chunk，而两条检索都只按 collection 过滤：`:880` 关键词、`:935` 向量，都不 join `RagDocument`、不看 `deleted_at`。触发：删一篇文档后问只有它能答的问题。现象：文档在列表里没了，AI 照样引用；误传的机密/作废价格表删了等于没删，只能删整个知识库。修：两条检索 join 文档加 `deleted_at.is_(None)`。

**H6 两个卡死的音频任务让用户永久 429**
`multimodal_audio_service.py:111-116` 统计「历史上所有 queued/processing」，无时间界，上限 2（`config.py:98`）；worker 领取即 `attempts+=1`，`attempts>=3` 后不再重领也不置 failed，容器重启（本仓每天 pin 好几次镜像）就会留下永久 processing。现象：该用户此后转写/语音合成一律 429，界面上没有任何入口能清掉。修：加 `locked_at`/`created_at` 时间界 + 启动时回收超租约任务。

## 5. 部署配置层的 bug

**D1 · nginx 50MB 上限 vs 代码 100MB。** `frontend/nginx.coolify.conf:42` `client_max_body_size 50m;`，而 `api/client.ts:1362` 的 SKILL_ARCHIVE_MAX_BYTES 与 `skill_import_service.py:283` 都是 100MB。50–100MB 的技能包/知识库文档拿到 nginx 的 HTML 413，`client.ts:1594` 的 `resp.json().catch(()=>({}))` 让用户只看到裸的 "Request Entity Too Large"。工作空间文件走直传 OSS 不受影响。

**D2 · storage-lifecycle 一遇 503 就回滚整小时的清理。** `workers/storage_lifecycle.py:22-31` 把 `run_cleanup` 和 `reconcile_orphan_objects` 放同一 session，任何异常 → `db.rollback()`；`storage_gateway_service.py:690` 只对 404/405/501 返回 None，503 直接抛。但 OSS 上已经执行的 `delete_object` 不会回滚 → DB 行继续指向已不存在的对象。prod 日志里那两次 503 就是这个。`:40-44` 失败时不更新 `last_orphan_scan`，于是每小时重试一次而不是每天。
