# 统一灼见助手与能力工具交接

## 已实现

- 全局页与企业应用侧栏复用同一 Task、历史、文件引用和未完成目标，用户只面对一个“灼见助手”。
- 每轮由服务端生成页面与业务对象上下文，并按当前角色、`authEpoch`、Manifest 和可用模型能力动态发现少量工具。
- 子系统以 Manifest Action 提供业务事实与操作；专业 AI 仅作为内部工具返回结构化草案，由统一主脑继续编排。
- 图片理解、图片生成、ASR、音频理解、TTS、音色设计和声音克隆使用供应商无关的平台工具；模型网关负责选择管理员配置的部署。
- 文件型任务只有工作空间提交成功并产生可信 Artifact 后才能完成；导航和确认卡片使用结构化 `uiIntent`，不解析模型正文。
- MiMo 思考模式的工具调用会原样回传供应商 `reasoning_content`，但不会向用户显示私有思考链。

## 边界

- 未恢复 RAG、Embedding、Reranker、用户 Skill、DSH 或视频工具。
- 未修改 `aifabei-subsystem-builder`、业务子系统或外部服务器。
- 企业业务权限继续只由角色并集决定；部门和用户身份不产生隐式业务权限。

## 验证

- 后端：全量业务套件 535 passed；迁移基线套件 4 passed。
- 前端：TypeScript、文件链接/事件/UI、CSV/文档、演示文稿、Bridge、管理员会话、中文登录反馈、响应式、额度、退役入口测试通过。
- 前端生产构建通过。
- `git diff --check` 通过。
