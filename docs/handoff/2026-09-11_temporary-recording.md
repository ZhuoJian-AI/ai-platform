# 临时录音与取消（本地实现，未部署）

- 延续 PLATFORM-VOICE-RELIABILITY-20260911，基线 `7580501`。
- 普通录音不再创建 WorkspaceFile。复用 MultimodalJob：签名直传 OSS、完成后校验大小、worker 校验 SHA-256 并转写、结束后回收。
- 新接口 `/api/v1/multimodal/recordings`、`/{job_id}/complete`、`DELETE /{job_id}`，绑定当前租户及主体；模型和存储地址由服务端决定。
- 取消会中止浏览器 PUT 并取消任务。已发往模型的请求不保证立即中断；worker 不再覆盖取消状态或继续重试，前端不会回填。
- 签名有效期结束前不删除对象，防止在途 PUT 重建对象；终态录音由现有音频 worker 定时回收。清理失败记录无敏感信息的警告并延后重试，不阻塞其他任务。
- 排队录音在执行前重新检查有效角色，读取结果也重新检查 ASR 权限；撤权后仍允许所有者取消自己的录音。
- 修补已有音频任务响应遗漏必需 `department_id` 字段的问题；该字段仅表达原有元数据，不用于新增授权。
- 未改变工作空间上传默认分片行为：仅短时录音显式采用已有网关的单 PUT 签名接口，仍受平台音频大小上限约束。
- 验证：12 项聚焦纯逻辑测试通过，Ruff 通过，前端类型检查通过。未进行数据库并发、真实 OSS 或真实麦克风验收，不以这些单元测试代替 E2E。
- 仍待：真实上传/取消/清理验证、按需朗读、沉浸式共享控制器及发布。未修改数据库 Schema、外部 Skill、业务子系统或数据盘。
