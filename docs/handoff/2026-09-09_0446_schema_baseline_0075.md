# 0075 后新安装单一 Alembic 基线

## 范围

- 以 `5bc98bf664219f5d5d04fcd17f1767dab0ff232a` 为基线。
- 仅修改 Alembic 环境、迁移文件和隔离 PostgreSQL 迁移测试。
- 未修改运行时代码、前端、Skill、部署文件或 staging。

## 实现

- 保持数据库 revision 为 `0075_retired_schema_contract`，将其改为唯一 root/head。已经处于 0075 的数据库再次执行 `upgrade head` 不会调用迁移函数或执行 DDL。
- 删除工作树中的 0001–0074 Python 迁移；全部历史仍可从 Git 恢复。
- 新安装由相邻的 `0075_schema_baseline.sql` 一次性创建最终 PostgreSQL Schema。迁移先验证 SHA-256 和 vector、额度函数、额度物化视图及 append-only trigger 标记，再通过 asyncpg 在同一 Alembic 事务执行。
- SQL 固定 pgvector `0.8.2`，包含 lock/statement timeout；不包含 `DROP ... CASCADE`，也不导入 ORM metadata 动态建表。
- 静态 SQL 保留历史升级库的物理列序号空洞，并使用原始 CHECK 表达式，使新安装结构指纹与 0001→0075 升级结果逐类别完全一致。
- `alembic/env.py` 只忽略 0075 已审计且指纹测试覆盖的明确 ORM 等价项：优化索引名称/形态、5 个历史 BIGINT 管理员外键。其他 Schema 漂移仍由 `alembic check` 拦截。

## 验证

```text
python -m pytest tests/test_migration_0075_baseline.py -q

python -m ruff check alembic/env.py alembic/versions/0075_retired_schema_contract.py tests/test_migration_0075_baseline.py

python -m compileall -q alembic/env.py alembic/versions/0075_retired_schema_contract.py tests/test_migration_0075_baseline.py

python -m alembic heads
0075_retired_schema_contract (head)

python -m alembic check
No new upgrade operations detected.
```

真实 PostgreSQL 测试覆盖：空库 `upgrade head`、核心扩展/函数/触发器/物化视图、精确 Schema 指纹、第二次 `upgrade head` 的关系 OID/relfilenode 不变，以及 `alembic check` 零漂移。

## 风险与恢复

- 这是 0075 已在线后的新安装基线，不再支持从源码运行 0001–0074 或迁回旧 revision。
- pgvector 版本不匹配会失败关闭，避免静默创建不同 Schema。
- downgrade 明确拒绝；恢复必须使用数据库快照与匹配镜像。
- 后续新增迁移应以 `0075_retired_schema_contract` 为 `down_revision`，并在变更 Schema 时同步更新 ORM；不得改写本基线 SQL。
