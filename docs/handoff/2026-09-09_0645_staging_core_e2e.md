# Staging 双端核心浏览器回归脚本

## 任务

基于执行时最新 `origin/main` 增加可复用的 staging 核心 Playwright 回归，使用相互隔离的浏览器上下文从真实登录页面进入管理员端和员工端。凭据仅在运行时由环境变量提供，不写入源码、报告、截图或 Trace。

## 改动

- 新增 `frontend/scripts/e2e-staging-core.mjs`。
- 新增 `npm run test:e2e:staging-core` 命令。
- 管理员侧覆盖：错误密码 401 与中文提示、真实登录、19 个保留导航、4 个隐藏直达页面、员工有效权限预览。
- 员工侧覆盖：错误密码 401 与中文提示、真实登录、4 个核心导航、实时有效权限。
- 对管理员预览与员工实时权限的角色和工作空间能力进行结构化一致性比较。
- 动态选择当前员工可见、已启用业务助手并含目标模块的内嵌应用，验证 iframe 真实渲染及 Bridge 当前模块连接。
- 发起带唯一 `E2E-<runId>` 标记的真实 Excel 请求，验证文件卡片、下载、OOXML 包、可信 Artifact、工作空间当前版本、SHA-256 和表格预览。
- 仅清理由本次唯一标记创建的对话和文件；文件通过正式接口移入回收站，不触碰既有任务、文件、权限或管理员数据。
- 任一步失败时再次按唯一标记发现并清理可能已创建的 E2E 对话和文件。
- 浏览器异常输出会脱敏密码、Bearer 和 URL 查询参数；默认禁止误跑非 staging 地址。

## 运行方式

在 `frontend` 目录设置以下运行时环境变量后执行：

```text
E2E_ADMIN_USERNAME
E2E_ADMIN_PASSWORD
E2E_USER_USERNAME
E2E_USER_PASSWORD
npm run test:e2e:staging-core
```

可选变量：`E2E_BASE_URL`、`E2E_ORG_SLUG`、`E2E_APPLICATION_ID`、`E2E_MODULE_KEY`、`E2E_BROWSER_EXECUTABLE`、`E2E_PROXY_SERVER`、`E2E_HEADLESS`、`E2E_ARTIFACT_TIMEOUT_MS`。

  - E2E 对话清理 1 条，E2E 文件移入回收站 1 个。

## 风险与边界

- 这是双端核心 smoke，不替代计划中的每个管理员 CRUD、全部 Manifest Action 和全部文件格式矩阵。
- 文件清理遵循产品语义进入回收站，因此审计记录和回收站痕迹会保留；脚本不会永久删除对象。
- 脚本不做真实角色授予/撤销，权限闭环采用管理员只读预览与员工实时权限深比较，避免在共享 staging 修改真实授权。
- 没有部署、没有修改数据库、没有修改业务子系统。
