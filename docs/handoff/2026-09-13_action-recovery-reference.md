# 原操作引用恢复工具

仅当当前 Task 的服务端助手历史中有对应 Action 的请求引用时，为该授权 Action 装配一个 resume_action 工具，参数只有原 requestId。引用上限 20，忽略用户消息、其他工具引用；不存在历史时不增加工具。页面加载与总入口动态目录沿用现有装配机制。

执行刷新用户主体，重新读取 Action 并检查当前角色、应用、模块、页面、请求所属用户与租户。历史页面不匹配、记录不存在或旧记录没有页面绑定时拒绝，不新建请求。返回原回执或原确认卡片，标记 replayed，完成时间使用原记录时间，不伪造当前执行成功。过期卡片不再返回可确认引用。读取恢复工具不自动确认，也绝不调用远端业务写入。

验证：135 项恢复/未知写入/核实/Action 聚焦测试，以及 1 项专业 AI 工具注册回归通过，共 136；Ruff 与 diff 检查通过。覆盖目录按历史装配、旧引用重放、权限撤销、错误页面、过期、缺失记录、跨动作/用户历史过滤。两处文件测试和一处策略测试 mock 补充新增可选 history_messages 参数，未重复运行其数据库全套测试。没有真人新业务写入验收，不把纯测试记为真实业务完成率。

边界：恢复入口不会重复写入，但模型如果不用恢复入口而重新调用原业务工具，跨轮逻辑操作归属和自动去重仍未完整实现。完整多目标恢复与真实模型组合验收继续保留待办。无新服务、数据库迁移或外部契约修改，不修改外部 Skill 和子系统。
