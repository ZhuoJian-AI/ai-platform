# 企业 AI 底座用户手册（超级管理员）

本文对应当前 9 服务版 AI Platform。超级管理员负责平台级企业、模型、权限和运行状态；员工实际使用入口是企业终端。

## 1. 登录与角色边界

- 管理入口：`/login`。
- 超级管理员可以管理全部企业及平台级配置。
- 企业管理员只管理绑定企业，不得访问其他企业数据。
- 员工账号与管理员账号相互独立；管理员权限不会自动成为员工业务权限。
- 所有管理操作都以服务端实时权限为准，不能依靠隐藏按钮代替鉴权。

## 2. 企业与权限

### 2.1 组织架构

用于维护企业、部门层级、部门状态和员工主部门。删除前应先处理仍被员工、角色或工作空间引用的部门。

### 2.2 企业模块

用于登记企业应用、同步 Manifest，并查看模块、页面和 Action。新页面和 Action 默认无权，必须在角色权限中明确授权。

### 2.3 角色权限与员工授权

- 一个员工可以绑定多个角色，最终权限取并集。
- 企业管理员的 `*` 表示全部部门工作空间读取、上传和修改；不自动批准新应用页面和 Action。
- 普通员工默认拥有个人空间读写和主部门空间只读；跨部门工作空间、应用页面及 Action 由角色授权。
- 角色或员工状态变化后会更新 `auth_epoch`，旧会话不能继续使用已经撤销的权限。
- 管理端的“模拟员工查看”与员工端调用同一权限服务，显示结果必须与真实接口一致。

员工管理支持创建、修改资料、调整主部门、增删角色、重置密码、启停和删除。保存失败时以前端显示的中文服务端错误为准；用户名冲突只在真实唯一约束冲突时返回。

### 2.4 管理员、企业资料和联系方式

管理员页面维护超级管理员和企业管理员；企业资料、联系方式分别维护企业展示信息和联系人。不要把员工账号放入管理员表，也不要把管理员账号当作业务员工使用。

## 3. 模型路由

### 3.1 API Key 管理

平台 API Key 用于调用公开 `/v1` OpenAI/Anthropic 兼容接口。创建、轮换、停用和删除都应结合审计记录验证；密钥只在创建时展示完整值。

### 3.2 模型提供商

维护 LLM、Embedding、多模态、图像和其他已支持模型的供应商地址、凭据与模型映射。供应商凭据只保留在平台，不下发到业务子系统或员工浏览器。

### 3.3 安全围栏、额度与审计

模型请求经过 DLP、模型路由、配额和审计。业务小助手与个人助手共用平台模型供应商和额度体系，业务系统不持有模型密钥。

## 4. Assistant Core

### 4.1 工作空间

工作空间保留文件夹、文件、版本、OSS 对象、上传、预览、下载、回收站和恢复。Office/PPT 只提供受控预览；在线协作编辑已经退役。

### 4.2 智能体

个人助手、业务小助手和自定义智能体统一由原生 Assistant Core 执行。自定义智能体只保存名称、说明和角色提示词，模型、工作空间、Web、多模态、长期记忆及平台固定文件工具均继承当前员工的个人助手能力与实时权限。

### 4.3 长期记忆与平台固定工具

长期记忆管理用户级 Markdown 记忆并按企业及员工身份隔离。平台固定文件工具由受控执行器运行，不接受用户上传脚本或任意代码。

### 4.4 业务小助手

业务小助手只装配当前企业应用、模块、页面实时授权的 Manifest Action，并携带 Bridge 页面上下文。文件型请求只有在真实文件写入当前员工有权工作空间、产生 Artifact 且能够预览或下载后才算完成。

## 5. 企业应用接入

平台保留 Manifest、Action、Event、一次性 SSO、Bridge、Runtime 和 ECS Publisher：

1. Runtime 登记或同步企业应用 Manifest。
2. 管理员审核应用、模块、页面和 Action。
3. 角色授权页面和 Action。
4. 员工通过企业终端打开嵌入页面。
5. Bridge 注入短时上下文；Action 每次调用都重新鉴权。

业务系统返回权限过滤后的业务数据；SaaS 负责模型调用、文件执行、工作空间提交和 Artifact 交付。

## 6. 监控与运维

- 总览：服务健康和关键运行状态。
- 路由器监控：模型调用、延迟和错误。
- 智能体监控：任务与运行事件。
- 工具监控：平台固定工具和 Manifest Action。
- Runtime 管理与 ECS Publisher：企业子系统登记、发布和诊断。

## 7. 员工终端

企业终端提供个人助手、企业应用、跨部门待办、工作空间和文本型智能体。员工看不到的资源不得通过直接 API、篡改 workspace ID、旧页面缓存或 iframe 绕过。

## 8. 已退役能力

以下产品及运行链路已经删除，不应再出现在导航、OpenAPI、环境变量或新文档中：

- DSH Runtime、市场、外部扩展和扩展构建器；
- Connector、Tool Endpoint、Data Interface/Data System；
- Ontology、Judge、管理员测试广场；
- MCP/OAuth Skill Pack、Team、ScopeManager；
- 旧 GitHub/Coolify 模块发布器和 WebOffice 在线协作编辑。
- 平台知识库/RAG、用户上传 Skill 及任意代码执行链路。

历史审计和迁移记录可能仍出现这些名称，仅用于追溯，不代表功能仍可使用。

## 9. 验收原则

- 管理员和员工必须使用独立浏览器会话实测。
- 每个保留页面都要真实打开，不得以接口 200 代替页面验证。
- CRUD 仅使用可识别并可清理的测试数据。
- 401、403、409、422 必须显示准确中文提示。
- 文件测试必须核对版本、预览、下载和回收站。
- 业务助手必须真实执行 Action 并交付工作空间 Artifact。
- 发布后应核对 9 个服务健康、数据库 revision、镜像 digest 和后端错误日志。
