## 1. 平台概览

企业 AI 底座（ai_infra）是一个统一的 AI 基础设施平台，围绕**大模型路由、智能体编排、工具接入、应用监控**提供一站式能力。平台由**五个一级菜单**组成，顶部菜单切换子系统，左侧菜单为当前子系统的功能页面：

| # | 一级菜单 | 定位 |
|---|---------|------|
| ① | 组织管理 | 组织架构 / 用户的层级化管理（组织管理员仅可见本组织） |
| ② | 模型路由器 | 统一 LLM API 中转：多提供商、API Key、模型提供商、安全围栏 |
| ③ | 智能体平台 | 基于 LangGraph 的智能体：工作空间、配置、RAG、判官、测试广场 |
| ④ | 工具连接器 | 外部系统接入、数据接口、技能、本体 |
| ⑤ | 应用监控台 | 路由器 / 智能体 / 工具 三子系统统一监控看板 |

**架构约定**：五个子系统共享同一套后端（组织架构 / Admin 鉴权 / 审计 / 数据库 / 加密 / 模型路由），由统一的控制台前端驱动。所有资源均**按组织架构作用域隔离**。

> 🔒 **组织管理员的核心约束**：你的账号被**绑定到单个组织**。你在所有子系统中**只能看到与操作本组织的资源**，跨组织访问会被后端拒绝（403）。顶部不再有「组织选择器」——组织已锁定，显示为本组织名称标签。

## 2. 登录与控制台布局

### 2.1 登录

- 登录地址为 `http://localhost:5173/{组织 slug}/login`（部署域名替换为实际域名，如 `https://ai.example.com/acme/login`）。登录框上方会显示你所属组织的名称。
- 用超级管理员为你创建的**用户名 + 密码**登录（非邮箱）。用户名在你所属组织内唯一，不同组织之间可以同名。
- 若是首次登录或密码被重置，会要求**强制修改密码**（`must_change_password` 标志），改密后进入控制台。
- 会话失效后会自动回到本组织的登录页（`/{slug}/login`）。

> ⚠️ 组织管理员账号由**超级管理员**在「管理员管理」中创建并指派组织；组织管理员自身**无权**创建或管理任何管理员账号。

### 2.2 控制台布局

- **顶部**：Logo + 五个一级菜单 + 当前用户（用户名旁绿色 `@ 组织名` + 角色标签 `[组织管理员]`）+ 退出。
- **左侧**：当前子系统的二级菜单。
- **主区**：功能页面。各页面顶部的「组织选择器」对本组织管理员显示为**不可点的蓝色组织名标签**——组织已锁定为本组织，无需也不能切换。

## 3. 组织管理员角色与权限边界

### 3.1 管理员角色体系

| 角色 | 标签 | 能力 |
|------|------|------|
| `super_admin` | 超管 | 全平台：创建/删除管理员、管理所有组织与资源、配置一切 |
| `admin` | 管理员 | 平台级管理员，管理**所有**组织的架构 / Key / 规则等资源（不能管理管理员账号） |
| `org_admin` | 组织管理员 | 仅管理**被指派的单个组织**内的全部资源（本手册角色） |

### 3.2 组织管理员的能与不能

**✅ 可以（本组织作用域内）：**
- 管理本组织的部门、团队、用户（增删改）。
- 配置本组织的模型提供商、API Key、DLP 规则、路由策略。
- 创建与编辑本组织的智能体、工作空间、RAG 集合、判官模板、工具连接器、技能、本体。
- 在测试广场运行本组织智能体。
- 查看本组织的审计日志、预算消耗、监控指标。

**❌ 不可：**
- 创建、删除、设为默认**组织**本身（平台级操作，仅超管/平台管理员可用）。
- 查看「管理员管理」二级菜单（对组织管理员隐藏）。
- 创建/编辑/删除任何**管理员账号**。
- 访问或操作**其他组织**的任何资源（后端强制 403）。
- 切换组织（顶部组织标签锁定为本组织）。

### 3.3 保护性约束（系统内置）

- 所有写操作均需 JWT 管理员认证。
- 所有资源查询与操作按 `organization_id` 作用域过滤；越权访问其他组织返回 **403 No access to this organization**。
- 平台级写接口（创建/删除组织、设默认组织、管理员 CRUD）对 `org_admin` 角色直接拒绝。

## 4. 组织管理（一级菜单①）

组织管理是全平台的**权限与作用域基座**。组织管理员在本菜单下**只见本组织**，下设两个可见二级功能（「管理员管理」对本角色隐藏）。

### 4.1 组织架构

建立 `组织 → 部门 → 团队` 三级层级。

- **组织**：顶层租户。组织管理员**只能查看**自己被指派的组织，左侧组织树**仅显示本组织**。
- **部门**：隶属于组织，继承并可在组织限额内收窄。
- **团队**：隶属于部门，同样可收窄限额。

> **限额级联规则**：模型列表取各级**交集**（子级只能缩小范围）；速率/预算上限取各级**最小值**（子级不能突破父级）。

**操作**：进入本组织 → 新建部门 → 进入部门新建团队。Slug 一经创建不可改。

> ⚠️ 组织管理员视图下，「创建组织」「设为默认」「删除组织」按钮**已隐藏**——组织本身的增删与默认设定是平台级操作，需联系超级管理员处理。部门与团队的增删改不受限制。

### 4.2 用户管理

管理本组织内的**终端用户**（区别于管理员，用户是组织成员，用于 API Key 的 `created_by` 归属等）。

- 字段：用户名、显示名、角色（`admin`/`member`）、启用状态、部门/团队绑定。
- 用户名（非邮箱）同组织内唯一，不同组织之间可以同名。
- 支持新建 / 编辑 / 删除（软删）。

> 「管理员管理」二级菜单对组织管理员**不可见**——组织内若有需要新增管理员账号的需求，须提请超级管理员处理。

## 5. 模型路由器（一级菜单②）

统一 LLM API 中转，是智能体平台与外部调用方共享的模型能力底座。本子系统所有数据与操作均**限定在本组织**。

### 5.1 API Key 管理

层级化 API Key 体系，Key 可绑定到 **组织 / 部门 / 团队**三级节点（**绑定节点**）。

- 页面左右分栏：左侧为**本组织**组织架构树（组织 → 部门 → 团队），选中某节点后，右栏列出**绑定到该节点**的 Key（组织节点看组织级 Key、部门节点看该部门 Key、团队节点看该团队 Key）。
- 创建时**绑定节点取自左栏选中节点**，Key 继承该节点及其上层的作用域与限额；未选节点时创建按钮禁用。
- 字段：Key 名称、绑定节点（只读）、允许模型列表（空=全部）、RPM/TPM/预算上限、过期时间。
- **编辑**可改名称、允许模型、速率/预算上限、过期时间、启用状态；绑定节点不可改。
- 创建后**仅展示一次完整 Key**，请立即保存；后续仅可见前缀。
- 支持 启用/停用/撤销。

### 5.2 模型提供商

注册第三方大模型连接与密钥（本组织作用域），支持组织/部门/团队三级。

- 页面左右分栏：左侧本组织架构树选择节点，右栏管理该节点绑定的提供商；创建时绑定节点取自左栏选中节点，绑定后不可改。
- **调用解析遵循 团队级 > 部门级 > 组织级 优先级且可继承**：团队调用方候选含团队+部门+组织级；部门级含部门+组织级；无下层时回退上层。
- 类型：Anthropic / OpenAI / Azure OpenAI / 自定义。
- 字段：名称、Base URL、API Key（AES-256-GCM 加密落库，**读回不回显明文**）、支持模型列表、优先级、权重、超时、重试、健康状态。
- 编辑时 API Key 留空表示保持原 Key 不变。

### 5.3 安全围栏

数据脱敏/拦截规则，作用于请求与响应双向。

- 页面左右分栏：左侧本组织架构树选择节点，右栏按节点 scope 过滤规则（组织节点=组织级规则，部门/团队节点仅各自 scope）。
- **规则库**为代码内置只读集合。新建组织时已自动播种全部内置规则为组织级（默认启用），本角色可逐条启停，或通过「添加规则」从规则库追加到本组织/部门/团队 scope。
- **添加规则**：从规则库选一条，配置 严重级别 / 执行动作 / 检测方向 / 范围 / 优先级 / 启用状态 共 6 项；名称/类型/匹配模式来自规则库不可改。同 scope 同名去重。
- **配置规则**：不可改名、不可改类型/匹配模式，仅配置上述 6 项。
- 列表「启动」开关可逐条启停；组织级/部门级/团队级规则本角色均可启停、配置与删除（无全局规则概念）。
- 规则类型：正则 / 关键词 / NER / 自定义；严重级：低/中/高/危；动作：拦截/脱敏/告警/记录；方向：请求/响应/双向。作用域：组织 / 部门 / 团队。
- 支持**规则测试**：输入文本 + 方向，预览命中与脱敏结果。

> 仪表盘、预算管理、审计日志已并入「应用监控台 → 路由器监控」（见 8.2），模型路由器不再单设此三页。

## 6. 智能体平台（一级菜单③）

基于 **LangGraph** 的智能体编排与管理。下设五个二级功能，全部**绑定到本组织**。

> **绑定节点约定**：智能体、判官模板在创建时均需选择**绑定节点**（组织/部门/团队，仅本组织子树），将资源绑定到组织架构节点（Slug 字段即节点 Slug，创建后不可改）。**RAG 知识库**在左栏架构树选中节点（组织/部门/团队/个人）后新建，自动归属到该作用域。**工作空间**不再手动绑定，而是随组织 / 部门 / 团队 / 用户节点自动生成。

### 6.1 工作空间

智能体文件读写的**沙箱根作用域**，随组织架构逐级嵌套。

- **自动生成**：新建组织 / 部门 / 团队 / 用户（终端用户）节点时，自动生成一个与该节点同名的工作空间，并按层级逐级嵌套（组织 → 部门 → 团队 → 用户）；节点重命名时工作空间名称同步，节点删除时其工作空间一并软删。工作空间只能通过组织节点的增删改自动生成，不支持手动新建。
- **文件夹树管理**：本页左右分栏——左侧以文件夹树展示本组织下全部工作空间节点，选中任一节点即在右侧进入其工作空间的文件管理。
- **网格浏览器**：选中节点后，右侧以网格浏览器管理工作空间内的**文件夹与文件**（支持嵌套、可新建空文件夹）——面包屑逐级进入文件夹、网格卡片展示文件夹与文件，所有操作按钮均为图标；可上传文件（文本与二进制均可：二进制以 base64 内联存储并支持下载）/ 查看 / 删除文件，新建 / 删除文件夹；删除文件夹将级联清理其下所有子文件夹与文件。文件路径中未显式建文件夹的中间目录亦会自动推导呈现，确保任意深路径文件均可浏览到。
- **查看文件**：点击文件的「查看」图标，以新标签页加载并直接呈现内容——文本（Markdown / HTML 渲染、纯文本）与二进制（图片、PDF 内嵌预览，其它二进制提供下载）均可直接呈现；多个文件各自独立 tab，可关闭。网格浏览始终为首个 tab，切换工作空间时自动清空查看 tab。
- **安全**：文件 / 文件夹路径自动规范化——剥离前导 `/` 与所有 `..` 段，确保智能体读写、输出文件不越出工作空间。

### 6.2 智能体

智能体配置中心。

- **基础**：名称、绑定节点、描述。
- **系统提示词**：agent 的角色与指令。
- **模型**：真实模型 id（如 `glm-5.2` / `claude-sonnet-4`），或 `default` 走组织默认路由。
- **绑定**：工作空间、RAG 集合、判官模板、技能 ID 列表。
- **Workflow**：节点定义（JSON）。
- **记忆配置**：`{"enabled": true, "max_messages": 10}`，启用后按会话持久化对话。
- **判官配置覆盖**：`{"enabled": true, "criteria_overrides": [...]}`。
- **推理参数**：Temperature、Max Tokens。
- 每次编辑自增版本号。

### 6.3 测试广场

运行本组织智能体并实时观察执行。

- 选择智能体后输入消息发送（组织已锁定为本组织，无需选择组织）。
- **流式输出**（SSE）：右侧「执行轨迹」实时展示步骤事件（load_config / RAG 检索 / LLM 调用 / 工具调用 / 判官）。
- 同一会话连续对话可保持上下文（启用记忆时）。
- 「运行历史」展示历次执行的状态、token、耗时。

**运行时流水线**（LangGraph StateGraph，7 节点线性）：

```
load_config → retrieve_rag → load_memory → agent_loop → save_memory → judge → write_run_log
```

- `agent_loop` 内部完成 **LLM ↔ 工具** 多步循环（最多 8 步，防死循环）。
- LLM 调用复用模型路由器的 provider 解析 / 密钥解密 / 路由能力（不走外部 /v1 HTTP）。
- 无可用 provider 时优雅降级：记录 error 并落 AgentRun（status=error），不抛 500。

### 6.4 RAG

知识库（pgvector 向量检索）。采用**左中右三栏**资源管理器式界面：

- **左栏·组织架构树**：本组织下的 组织 / 部门 / 团队 / 个人 四级，选中节点确定中栏知识库的作用域。
- **中栏·知识库**：列出选中节点作用域下的知识库，可**新建 / 重命名 / 删除**；新建时知识库自动归属到左栏选中的作用域节点，嵌入模型默认取本组织「入库参数配置」，分块大小/重叠可在表单内调整。
- **右栏·文件夹与文档**：当前知识库内的文件夹与文档，可**新建 / 重命名 / 删除文件夹**、**上传 / 重命名 / 删除文档**；删除文件夹会级联删除其下所有内容。顶部面包屑支持逐级返回。
- **文档入库**：填来源/标题/内容，系统按集合分块策略自动**分块 + 嵌入**落库（embedding 失败时仍保留文本块，检索时跳过），并可指定归属文件夹。
- **入库参数配置**（右上按钮）：设定本组织默认的嵌入模型 / 分块大小 / 重叠 / 检索 Top-K，作为新建知识库与入库的默认值。
- **检索测试**：选中知识库后输入查询，返回 top-k 命中（含余弦相似度 score）。
- 向量列维度无关，不同嵌入维度的集合可共存。

> 嵌入需本组织下配置一个 OpenAI 兼容类型的模型提供商（Anthropic 不提供嵌入端点）。

### 6.5 Judge 模板

可复用的 LLM-as-judge 评分模板。

- 字段：名称、绑定节点、评分维度 `[{dimension, weight, description}]`、评分细则、启用。
- 可被多个智能体引用；智能体可再以 `judge_config` 覆盖。

## 7. 工具连接器（一级菜单④）

外部系统接入与智能体可调用的技能/本体。下设三个二级功能，全部**绑定到本组织**。左侧组织架构树用于定位节点（组织 / 部门 / 团队 / 个人作用域）。

### 7.1 数据接口

独立的数据结构（系统 + 数据接口），按节点作用域管理。**左中右三栏**：组织架构树 · 系统 · 数据接口。

- **系统**：列表展示选中节点作用域下的系统，仅支持 **启用 / 禁用**（创建/编辑/删除不在此页暴露，由后端 API 录入）。
- **数据接口**：选中系统后展示其接口列表，支持 **启用 / 禁用**、按名称/路径/方法 **搜索**、**查看输入输出样例**（`params_schema` 输入参数、`response_schema` 输出响应）。
- 数据接口与连接器（技能绑定 / agent 调用）解耦，互不影响。

### 7.2 技能

智能体可调用的 function-tool，**以文件夹形式存储**。左右分栏：组织架构树 · 技能操作区。

- 一个技能即一个文件夹；文件夹内 `skill.md` 定义函数（名称、描述、参数结构、绑定的端点）。
- 操作：**上传**（新建技能文件夹 / 补传文件）、**删除**、**查看**、**重命名**、**搜索**。
- 终端运行任务时按员工权限自动匹配可见技能并装配为可调用工具；在终端任务输入框用 /技能-slug 引用具体技能时，智能体执行时主动调用。

### 7.3 本体

以 **Markdown 文件** 描述业务对象，按文件夹组织。左右分栏：组织架构树 · 本体操作区。

- 本体为 Markdown 格式；支持 **文件夹新建 / 删除 / 重命名**。
- 本体文件支持 **上传 / 删除 / 查看 / 重命名 / 编辑 / 搜索**。
- 终端运行任务时按员工权限自动注入可见本体 Markdown 至智能体上下文，无需在任务资源配置中手动指定。

## 8. 应用监控台（一级菜单⑤）

三子系统统一监控，默认统计**近 24 小时**数据。所有指标**仅本组织**。下设总览与三个明细页。

### 8.1 总览

三子系统汇总卡片 + 调用量对比柱状图（recharts）：
- 路由器请求 / 错误率 / DLP 违规
- 智能体运行 / 成功率
- 工具调用 / 错误率

### 8.2 路由器监控

整合原仪表盘、预算管理、审计日志三页为四张 Tab，统一按选中组织呈现（均限定本组织）：

- **概览**（原仪表盘）：组织 / 模型提供商 / 活跃 API Key / DLP 规则 四张计数卡 + 活跃提供商列表 + 快速入门。
- **路由指标**：数据源 `audit_logs`——总请求、输入/输出 token、平均延迟、错误数、DLP 违规数；按 Provider 明细表（请求数 / token）。
- **预算消耗**：按 API Key × Provider 维度实时聚合本月 token 消耗（输入/输出/总量/请求数/消耗进度），可切换显示已删除 Key，展开查看各 Provider 明细。
- **审计日志**：append-only 调用日志，按事件类型、时间窗、分页过滤；记录不可篡改。
- 统计全量 LLM 调用：外部 API Key 经代理端点的请求记为 `proxy_request`；智能体运行时直连上游的调用记为 `agent_request`（其 token 与 8.3 智能体监控存在重叠，按需对照）。

### 8.3 智能体监控

数据源 `agent_runs`（本组织）：
- 总运行、成功次数、成功率、token、平均延迟。
- 按智能体明细表（运行数 / token）：终端通用智能体的执行模式 Craft / Plan / Ask 各占一行；测试广场具名智能体按名展示。
- 组件用量：工作空间（使用运行数 / 文件操作次数）、RAG 知识库（检索运行数 / 命中片段数）、长期记忆（载入运行数 / 载入事实数 / 沉淀运行数 / 沉淀事实数），均由 `agent_runs.steps` 轨迹聚合。

### 8.4 工具监控

围绕「连接器 / 数据接口 / 技能 / 本体」四组件组织（本组织）：

**调用指标**（数据源 `tool_call_logs`，近 24h，运行时经 executor 落库，带 connector_id / endpoint_id / skill_id）：
- 总调用、成功、错误数、错误率、平均延迟。
- 按连接器明细表：连接器 / 类型 / 健康 / 启用 / 调用数 / 错误数 / 错误率 / 平均延迟 / 最近调用。
- 按技能明细表：技能 / 作用域 / 调用数 / 错误数 / 平均延迟（skill_id 关联 SkillFolder）。
- 按端点明细表：端点 / 所属连接器 / 方法 / 路径 / 调用数 / 错误数 / 平均延迟。

**资源盘点**（全量库存 + 状态，不按时间窗口）：
- 工具连接器：总数 / 启用 / 停用 + 健康分布（healthy / degraded / down / unknown）。
- 数据接口：系统数 / 接口数 / 启用 / 停用（运行时不被调用，仅管理态启用与样例查看）。
- 技能：技能文件夹数 / 文件数（SkillFolder / SkillFile）。
- 本体：文件夹数 / 文件数（OntologyFolder / OntologyFile，运行时注入 prompt，非工具调用）。

## 9. 安全与合规要点

| 维度 | 机制 |
|------|------|
| 认证 | 管理端全量 JWT；API Key 走代理鉴权（哈希比对 + 限额） |
| 授权 | 三级管理员角色 + 组织架构作用域过滤；org_admin 跨组织被 403 拒绝 |
| 作用域 | 组织管理员账号绑定单个 `organization_id`；所有资源查询/操作按本组织隔离；新资源经**绑定节点**挂到本组织内 org/dept/team |
| 密钥保护 | 模型提供商 Key、连接器鉴权配置均 AES-256-GCM 加密落库，读回不回显明文 |
| 数据安全 | DLP 双向围栏（请求/响应），可拦截/脱敏/告警/记录 |
| 文件沙箱 | 工作空间路径规范化，防 `..` 越权 |
| 预算控制 | 组织→部门→团队→Key 四级预算级联（取最小值） |
| 审计 | 路由器调用 append-only 审计日志；智能体执行落 AgentRun；工具调用落 ToolCallLog |

## 10. 常见问题与排错

**Q1：顶部没有「组织选择器」下拉了？**
A：这是设计预期。组织管理员的组织已**锁定为本组织**，显示为蓝色组织名标签，不可切换。所有页面数据自动限定为本组织。

**Q2：左侧「组织管理」下看不到「管理员管理」菜单？**
A：组织管理员无权管理管理员账号，该菜单对本角色**隐藏**。如需新增/重置管理员账号，请联系超级管理员。

**Q3：组织架构页看不到「创建组织/删除组织/设为默认」按钮？**
A：这些是平台级操作，仅超级管理员/平台管理员可用，对本角色隐藏。你可在本组织下正常增删部门与团队。

**Q4：测试广场提示「(执行出错: no provider available for model ...)」**
A：本组织下未配置支持目标模型的模型提供商，或提供商健康状态为 down。到「模型路由器 → 模型提供商」为本组织注册一个支持该模型的活跃提供商。

**Q5：RAG 检索无命中 / 入库后 embedding 为空**
A：嵌入需 OpenAI 兼容类型的提供商。确认**本组织**下有此类提供商且 `embedding_model` 名称正确；嵌入失败时文本块仍入库但无向量，检索会跳过。

**Q6：新建智能体时「Slug」字段是树选择器？**
A：该字段即**绑定节点**——从**本组织子树**选择 org/dept/team 节点，资源绑定到该节点。创建后不可改。工作空间无此字段，随组织节点自动生成。

**Q7：忘记密码 / 账号被停用**
A：组织管理员无权自助重置或管理账号，请联系超级管理员在「管理员管理」中重置密码或启用账号。重置后下次登录强制改密。

**Q8：DLP 误拦截正常请求**
A：到「安全围栏」用**规则测试**定位命中规则，调整本组织规则的严重级/动作（如改拦截为告警）或缩小作用域，必要时直接停用或删除该规则。

**Q9：监控台数据为空**
A：监控统计近 24 小时数据；若新部署且本组织无调用，指标为 0 属正常。产生一次调用（如测试广场运行一次智能体）即可在「智能体监控」看到数据。

**Q10：如何获取后端 API 文档**
A：开发环境下访问 `http://localhost:8000/docs`（Swagger）或 `/redoc`。注意：跨组织资源接口对本组织账号返回 403。

## 11. AgileBuddy（终端用户端）

面向本组织员工的独立门户，与管理控制台分离；核心是「新建任务 → 通用智能体执行」。

### 11.1 入口与登录

- 登录地址：`{域名}/{本组织 slug}/terminal/login`，登录框上方显示组织名。
- 使用「组织管理 → 用户管理」中创建的员工账号（用户名 + 密码）登录，进入 `/{slug}/terminal`。
- 在「用户管理」为员工绑定部门/团队，员工才能命中对应级别的资源与记忆。

### 11.2 通用智能体与资源配置

- 新建任务：填标题与任务描述 →「资源配置」选择工作空间 / 模型 →「开始执行」。
- 工作空间：以树状选取（仅显示当前员工权限可见的工作空间：组织 → 部门 → 团队 → 个人），指定后智能体读写的文件、输出文件均落在该工作空间内（list / read / write / delete）。
- 技能：无需在资源配置预选；运行时按员工权限自动装载全部技能为可调用工具。在输入框点「技能」或键入 / 弹出技能下拉，选中即以高亮标签形式插入 /技能-slug 引用（整体插入、退格键整体删除，不会被拆散），智能体执行任务时主动调用被引用的技能。
- 工作空间文件：在输入框点「文件」或键入 @ 弹出工作空间文件下拉，列出当前员工可访问的全部工作空间（组织 + 部门 + 团队 + 个人）内的文件；选中即以高亮标签插入文件引用（整体插入/删除），执行时该文件内容自动注入智能体上下文（二进制文件只引用不内联）。
- 本体：无需配置，运行时自动注入当前员工可访问的全部本体（组织 + 部门 + 团队 + 个人作用域并集）至智能体上下文。
- RAG 知识库：无需配置，运行时自动检索当前员工可访问的全部知识库（组织 + 部门 + 团队 + 个人作用域并集）。
- 长期记忆：无需配置，运行时按员工权限自动载入 组织 + 部门 + 团队 + 个人 四级长期记忆；个人级由智能体执行后自行沉淀。
- 执行流式呈现，右侧面板展示资源、工作空间文件、载入记忆与逐步轨迹；同一任务可多轮对话。

### 11.3 长期记忆

- 「智能体平台 → 长期记忆」以组织架构树呈现本组织全部长期记忆（均以 markdown 存储）。每个组织/部门/团队/用户节点创建时自动生成一条同名绑定记忆，按 组织→部门→团队→用户 逐级嵌套。
- 组织记忆写组织名，部门写组织+部门名，团队写组织/部门/团队名（`## 档案` 分节）；个人级每用户只有一份，由系统端同步的「个人档案」与终端智能体沉淀的「沉淀记忆」自动合并进同一条记录。
- 点击树节点在右侧编辑区修订其内容；记忆随节点增删改自动生成/同步，不手动新建/删除。组织/部门/团队记忆的 `## 档案` 分节由系统按节点名称同步（可覆写），其它分节可自由编辑；个人记忆 `## 个人档案`（系统同步）+ `## 沉淀记忆`（智能体逐条追加去重），可手动修订。
- 终端执行时按 用户 → 团队 → 部门 → 组织 四级聚合载入相关记忆注入系统提示词。

> 反馈与改进：本手册随平台迭代更新，新增子系统功能请同步补充对应章节。组织管理员的权限边界以系统内置约束为准（见第 3 章）。
