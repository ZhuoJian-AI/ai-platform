第一章　空调企业基本情况与业务痛点

1.1 敏睿空调企业概况

敏睿空调（AgileAC）是一家纵贯家用 + 商用空调研发 / 制造 / 销售 / 服务全产业链的集团企业，既是制造商也是销售商。覆盖自研产品（家用壁挂 / 柜机 / 移动 + 商用多联机 / 风管机 / 模块机组）与核心配件（压缩机 / 换热器 / 阀件 / 制冷剂），并通过经销 / 电商渠道与工程项目网络触达客户。企业已上线 PLM / SCM / ERP / MES / CRM / HRM 六大业务系统，但系统间数据各自为政，一线员工日常决策高度依赖人工跨系统巡查、Excel 汇总与反复登录。

主营品类：家用壁挂（P-RC-WALL-15）/ 柜机（P-RC-CAB-30）/ 移动（P-RC-MOVE-10）；商用多联机（P-CC-VRV-360）/ 风管机（P-CC-DUCT-50）/ 模块机（P-CC-CHILL-100）
核心配件：压缩机 M-COMP-GT-24K · 换热器 M-COND/M-EVAP-FIN-30 · 电子膨胀阀 M-EEV-15 · 制冷剂 M-RF-R410A
组织架构：研发部 / 产品部 / 生产制造部 / 质量部 / 供应链部 / 销售部 / 售后服务部 / 市场部 / 财务部 / 人力资源部 / 信息技术部（11 个归口部门）
业务系统：PLM · SCM · ERP · MES · CRM · HRM（6 套系统，跨表数据闭环）

本 POC 以「员工 vibe working 副驾驶」为定位：AI 是员工的辅助工具、不对终端客户直接交互（如 AI 语音接听客户来电等对外服务不纳入），由员工制作 / 决策后自行投放。

第二章　十一大场景的 AI 解决方案

十一个场景都用同一种终端任务方式：业务用户用自己的归口账号登录终端，新建一个任务、选好模型（glm-5.2）、粘贴一段很简短的提示词（写明"要做什么 + 针对哪些对象"后用 /技能名 引用技能）即可运行。智能体会自己判断该调用哪些业务系统、按什么顺序查，跨系统把数据凑齐，边算边输出结构化结果，最后还自动生成一份 .docx 报告可直接下发。用户提示词之所以能写得很短，是因为"输出格式、业务名词字典、智能体的人设与规则"这些已由平台和模板预先配好，用户只补"本次目标"即可。

📖 名词速查（看不懂的术语先看这里）
归口部门：负责某项业务的部门。本指南里每个场景都由一个归口部门用自己的账号去跑。
vibe working：AI 作员工的副驾驶辅助日常工作，不对终端客户直接交互。
BOM：物料清单，即一件产品要用的所有材料明细。
RAG：检索增强生成——让 AI 先在企业自己的知识库里检索相关内容、再据此作答，而不是凭空编。
本体：用 Markdown 写的业务"字典"，告诉 AI 每个业务名词是什么、有哪些字段和编码规则。
端点：业务系统提供的一个个查询接口（比如"查工单"就是一个端点）。
技能（skill）：把一组端点打包成"功能工具"，智能体用 /技能名 引用。
流式输出：AI 边算边把结果一段段吐出来，不用等全部算完才看到。
闭环 / 8D：把处理结果写回业务系统留痕，使整件事有始有终、可追溯；8D 是八阶段问题闭环法。
作用域（scope）：某个资源的可见范围，按 组织→部门→团队→用户 逐级限定。
SSO 免登：财务对账时终端一次登录，跨 ERP/MES/SCM/PLM 调用无需重复登录。
glm-5.2：本 POC 使用的大模型（智谱出品），终端下拉直接列真实模型 id。

第三章　AI 底座管理端配置

ai_infra 控制台顶部为五个一级菜单（子系统），左侧为当前子系统的功能页面；所有资源按组织架构隔离。本章按子系统逐页介绍每个功能页（参照平台帮助文档），并附敏睿空调组织（以 admin 登录）下的真实页面截图。登录后组织自动锁定为当前管理员被指派的那个组织（顶部以蓝色标签展示本组织名，无需手动切换），所有查询自动限定在本组织内。管理员（admin）可管理本组织的组织架构、API Key、安全规则、智能体、工具等资源，但不能管理管理员账号；不可删除自己、不可降级自己。

3.1 平台总览与四组件

平台是一站式 AI 基础设施，提供大模型路由、智能体编排、工具接入与应用监控四类能力，由四个子系统共享同一套后台控制台与基础设施（数据库 PostgreSQL + 缓存 Redis + 向量库 pgvector）。

子系统定位核心能力
组织管理权限地基组织→部门→团队三级层级、管理员与用户管理、速率/预算限额逐级收紧
模型路由器统一大模型中转API Key、模型提供商、DLP 安全围栏、模型路由与用量管控
智能体平台智能体编排工作空间、智能体配置、RAG 知识库、长期记忆
工具连接器业务系统接入数据接口、技能（功能工具）、本体
应用监控台三子系统统一看板调用量、Token、延迟、错误率、DLP、成功率

3.2 组织管理

组织管理是全平台的权限地基。先建"组织 → 部门 → 团队"三级层级，每一级都能设两道上限：①速率（每分钟最多调用多少次、每分钟最多用多少 Token）②预算（最多花多少美元 / 用多少 Token）。下级能用的模型、速率和预算上限只能在上级范围内再收紧、不能突破上级；组织创建时的网址标识（Slug）一经设定不可修改。

组织架构

三栏列表：组织 → 部门 → 团队。选中组织展示其下部门、选中部门展示团队；可创建/编辑/删除组织与部门、设为默认组织。敏睿空调下已建 11 个归口部门（研发 / 产品 / 生产制造 / 质量 / 供应链 / 销售 / 售后服务 / 市场 / 财务 / 人力资源 / 信息技术），24 个团队。

3.3 模型路由器

统一的大模型中转站：分层级的 Key 体系、多家模型提供商管理、DLP 安全围栏。找 Key 时按 团队级 > 部门级 > 组织级 的顺序优先匹配（下级没配就沿用上级的）。

API Key 管理

每个 Key 绑定到组织/部门/团队某个节点，自动继承该节点及其上层的可见范围与限额。左栏组织架构树选节点、右栏管理该节点绑定的 Key；创建时可填允许调用的模型（留空=全部）、速率/预算上限、过期时间。完整 Key 仅创建时显示一次，之后只可见前缀；支持启用/停用/撤销。敏睿空调下 16 个 Key（组织级默认 + 15 个团队级场景 Key）。

图 3-3　API Key 管理（分部门 / 团队签发 + 速率/预算上限）

模型提供商

登记要对接的大模型厂商（即"提供商"），支持组织/部门/团队三级可见范围。类型含 Anthropic / OpenAI / Azure OpenAI / 自定义，需填接口地址（Base URL）、密钥（API Key）、支持的模型清单、优先级、权重、超时、重试次数。密钥加密存储，编辑时留空表示沿用原值不改。敏睿空调下 3 个活跃提供商（智谱 glm-5.2 / Anthropic / DeepSeek 等经此路由）。

安全围栏

对发给大模型的请求和返回的响应双向做脱敏/拦截。规则库是平台内置的只读模板（涵盖个人隐私信息、财务、凭证、医疗、文件等类别），通过"添加规则"选用并配置严重级别、动作、方向、生效范围、优先级、是否启用。规则可按正则/关键词/NER（自动识别人名、公司名、金额等敏感信息）/自定义匹配；严重级分 低/中/高/危；动作分 拦截/脱敏/告警/记录；并提供"规则测试"预览命中与脱敏后的效果。敏睿空调下 9 条规则（组织级生效）。

3.4 智能体平台

基于流程编排：运行时按"加载配置 → 检索知识库(RAG) → 载入长期记忆 → 智能体与工具多步往返（大模型边想边调业务系统）→ 保存记忆 → 写运行日志"的顺序执行，结果边算边流式输出。智能体创建时选"绑定到哪个节点"（组织/部门/团队），绑定后不可改；RAG 在左栏选中节点后新建、归属该范围；工作空间随节点自动生成。

工作空间

智能体专用的文件读写区（沙箱，彼此隔离），随组织架构逐级嵌套（每建一个组织/部门/团队/用户节点，就自动生成一个同名工作空间）。左栏组织架构树、右栏网格浏览器：沿面包屑进文件夹、用网格卡片展示文件夹与文件；支持新建文件夹/上传文件/查看/删除，文件路径自动规整、不会越出本节点范围。敏睿空调下 52 个工作空间。

图 3-6　工作空间（售后工程师个人沙箱文件管理）

智能体

智能体是流程编排的核心——一个 agent = 一份人设（system_prompt）+ 可选的 RAG 知识库 + 工作空间 + 判官模板，定义了"以什么角色、按什么规则、调哪些工具、输出什么结构"来完成任务。运行时按"加载配置 → 检索知识库(RAG) → 载入长期记忆 → 智能体与工具多步往返 → 保存记忆 → 写运行日志"执行，结果边算边流式输出。敏睿空调采用四层架构模板：人设 / 业务规则 / 输出骨架由 agent 模板的 system_prompt 承载，用户终端只写"目标 + 对象 + 技能"几十字提示词，任务 config 绑 template_agent_id 即可继承技能与模型。

智能体创建时选"绑定到哪个节点"（组织 / 部门 / 团队），绑定后不可改；左栏组织架构树选节点、右栏管理该节点下的智能体（查看 / 编辑 system_prompt、绑定的 RAG / 工作空间 / 技能）。敏睿空调按 11 个场景归口部门建了 11 个业务智能体（全部门级 scope，销售部 2 个对应 SAL-01 / SAL-02）。

3.7 分级 scope 安全模型

敏睿空调所有资源按组织 / 部门 / 团队三级 scope 分级（区别于全组织级共享）：6 套业务系统与 7 域组织级本体组织级共享（全员可见）；部门级技能 / RAG / 本体按归口部门隔离；团队级资源（研发翻译组、招聘组）更细粒度。每个场景的归口用户登录后只能看到本部门 / 团队可见范围内的资源 + 组织级共享。安全隔离落在技能层：同一套组织级端点，不同部门技能只绑本部门授权的子集。

场景归口可见本体可见数据接口可见技能可见 RAG
研发翻译员组织级 7 域 + 研发翻译组本体组织级 6 系统（PLM 端点等）/agileac-rnd-plm-query多语术语库（团队级）
售后工程师组织级 7 域 + 售后服务部本体组织级 6 系统/agileac-svc-crm-mes-plm-query售后故障库（部门级）
销售运营员组织级 7 域组织级 6 系统/agileac-sal-crm-erp-query员工综合库（组织级）
排产计划员组织级 7 域组织级 6 系统/agileac-mfg-mes-erp-scm-query—（无 RAG）
🔒 为什么"分级 scope"是安全的
  • 最小可见面：业务用户只能看到本部门 / 团队被显式授权的技能与 RAG，跨部门敏感数据（如售后故障库对销售部、供应商资质库对研发部）默认不可见。
  • 技能层隔离：6 套系统组织级共享，但部门级技能只绑本部门授权端点子集——研发部技能只调 PLM 翻译端点、售后部技能调 CRM+MES+PLM 只读子集，暗箱穿透被技能 scope 阻断。
  • API Key 分团队签发：15 个团队级 Key + 组织级默认 Key，各自 RPM/token 预算上限，单团队异常不影响其他部门。
  • DLP 围栏组织级生效：客户名单、供应商报价等敏感数据外发规则按范围配置，越权外发即阻断/告警。
