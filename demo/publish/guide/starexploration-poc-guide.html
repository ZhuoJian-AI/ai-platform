第一章　勘探设计企业基本情况与业务痛点

1.1 星途勘探企业概况

星途勘探（StarExploration）是国内大型综合性工程设计研究院，隶属国机集团，业务覆盖工程咨询 / 勘察 / 设计 / EPC 总承包 / 项目管理 / 监理 / 运营运维 / 检测检验全生命周期。三大业务领域：工业工程（电工装备、新能源电池与材料、工程机械、有色冶金、智能制造，在电池全产业链工程设计领域具备核心竞争优势）、能源环保（光伏风电、分布式能源、供热输变电、水环境治理、固废处理、海绵城市，服务"双碳"战略）、城乡服务（民用建筑、市政工程、风景园林、城乡规划，支撑新型城镇化）。企业属典型的知识密集型、项目驱动型企业，多专业协同复杂、合规与质量要求严格、项目地域分布广，且为涉密资质单位，保密管控为核心特色。企业已上线 ERP / HRM / CRM 三大业务系统，并针对勘探设计特有场景新建 DES 设计管理 / EPC 工程项目 / SEC 保密与合规 三套系统，共 6 套；但各业务系统独立运行、数据分散在设计、项目、财务、人事等多系统，全流程数据贯通不足，方案比选、合规校验、进度成本、涉密管控等高度依赖人工跨系统巡查与经验判断。

设计方案：SCH-IND-001 电工装备厂房 / SCH-BAT-001 锂离子电池工厂 / SCH-CIV-001 市政污水处理厂
图纸：DWG-ARC- 建筑 / DWG-STR- 结构 / DWG-MEP- 机电
工程项目：PRJ-IND-001 电工装备厂房 EPC / PRJ-BAT-001 电池工厂 EPC / PRJ-CIV-001 市政水厂 EPC
涉密文档：SECDOC- 基础计算书 / 核心工艺参数 / EPC 合同（密级 机密/秘密/内部）
业务系统：ERP · HRM · CRM + DES · EPC · SEC（6 套系统，跨表数据闭环）

本 POC 以「员工 vibe working 副驾驶」为定位：AI 是员工的辅助工具、不对终端客户直接交互，由员工制作 / 决策后自行投放。

第二章　九大场景的 AI 解决方案

九个场景都用同一种终端任务方式：业务用户用自己的归口账号登录终端，新建一个任务、选好模型（glm-5.2）、绑定预配置的模板智能体、粘贴一段很简短的提示词（写明"要做什么 + 针对哪些对象"）即可运行。智能体会自己判断该调用哪些业务系统、按什么顺序查，跨系统把数据凑齐，边算边输出结构化结果。用户提示词之所以能写得很短，是因为"输出格式、业务名词字典、智能体的人设与规则"这些已由平台和模板预先配好，用户只补"本次目标"即可。

📖 名词速查（看不懂的术语先看这里）
设计方案（SCH-）：工程方案编号，如 SCH-IND-001（电工装备厂房方案）。
图纸（DWG-）：专业图纸，DWG-ARC- 建筑 / DWG-STR- 结构 / DWG-MEP- 机电。
工程项目（PRJ-）：EPC 总承包项目，如 PRJ-BAT-001（电池工厂 EPC）。
涉密文档（SECDOC-）：涉密图纸/合同/工艺参数，密级 机密/秘密/内部。
归口部门：负责某项业务的部门，每个场景由一个归口部门用自己的账号去跑。
vibe working：AI 作员工的副驾驶辅助日常工作，不对终端客户直接交互。
RAG：检索增强生成——让 AI 先在企业知识库检索相关内容、再据此作答。
本体 identifiers：业务"字典"，告诉 AI 每个编码是什么、跨系统怎么映射（防 404）。
技能（skill）：把一组业务系统端点打包成"功能工具"，智能体引用即用。
感知类端点：传文本画面描述返识别结果+整改工单，不生成图片/视频。
作用域（scope）：资源可见范围，按 组织→部门→团队→用户 逐级限定。
glm-5.2：本 POC 使用的大模型（智谱出品），终端下拉直接列真实模型 id。

第三章　AI 底座管理端配置

前两章是业务用户在终端的体验，本章是管理员（admin）在管理端为组织做的配置。管理员可管理本组织的组织架构、API Key、安全规则、智能体、工具等资源，但不能管理管理员账号、不可删除/降级自己。管理端由组织管理 / 模型路由器 / 智能体平台 / 工具连接器 / 应用监控台五大组件构成，以下逐页说明（截图均为星途勘探组织实测）。

3.1 平台总览与四组件

ai_infra 平台由五大组件构成：组织管理（组织/部门/团队/用户与权限边界）、模型路由器（多家 LLM 提供商 + API Key + 安全围栏 DLP）、智能体平台（智能体 + 工作空间 + RAG 知识库 + 长期记忆）、工具连接器（数据接口 + 技能 + 业务本体）、应用监控台（路由器/智能体/工具调用监控）。终端用户门户与管理端共用同一套后端，资源按 scope 分级可见。

3.7 分级 scope 安全模型

平台按 组织 → 部门 → 团队 → 用户 四级 scope 限定资源可见性。组织级资源（本体、数据接口目录、DLP 规则、组织级 RAG）全员可见；部门级资源（技能、部门级 RAG、智能体）仅本部门可见；团队级资源（团队 API Key、工作空间）仅本团队可见；用户级资源（长期记忆、个人工作空间）仅本人可见。终端任务勾选归口部门技能后，智能体只暴露 bound 端点对应的工具，自然实现部门级数据可见性边界——例如设计研究院的归口用户只能调 DES+ERP 端点，看不到保密办公室的 SEC 涉密数据。

跨系统 no-guessing 防护

每域 identifiers.md 写明编码前缀与跨码空间映射规则，智能体跨系统调用时按字段跳转而非直传异构编码，杜绝 404：算量项 QTI-CON-↔物料 M-CON-（prefix 转换）、方案 SCH-BAT-001↔项目 PRJ-BAT-001（按 scheme_no）、发票 INV202607001↔凭证 BV-SE-2026-0701（按 invoice_no）、涉密文档 SECDOC-.source_doc↔图纸 DWG-（按来源文档号）。
