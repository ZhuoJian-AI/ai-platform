第一章　热熔胶企业基本情况与业务痛点

1.1 星途热熔胶企业概况

星途热熔胶（StarHMA）成立于 2005 年，总部位于杭州未来科技城，是国家高新技术企业 / 专精特新企业，专注环保热熔胶 / 热熔压敏胶研发与生产。企业现拥有 13 条产线（其中 2 条全自动产线），年产能 2 万吨，累计服务 4500+ 客户，覆盖汽车内饰 / 医疗 / 食品日化包装 / 物流快递袋 / 鞋材箱包 / 粘扣带 / 家居七大下游行业。战略方向：由胶粘剂制造商向「粘接解决方案服务商」转型，按下游行业工况提供定制化配方与粘接方案。配方数据为核心商业机密，需本地私有化部署，AI 底座与 LLM 路由均落在本组织可控范围。企业已上线 ERP / MES / CRM 三大业务系统，并针对热熔胶行业特有场景新建 FRM 配方研发管理 / PCM 工艺与设备管理 / QAS 质量与技术服务 三套系统，共 6 套；但各业务系统独立运行、数据分散在配方、工艺、生产、库存、客诉等多系统，全流程数据贯通不足，配方推荐、实验分析、排产、库存、售后故障等高度依赖人工跨系统巡查与经验判断。

配方（FORM-）：FORM-STD-001/002/003 标准品 / FORM-CUS-001/002/003 定制配方
组分（ING-）：ING-RES- 树脂 / ING-TK- 增粘 / ING-WAX- 蜡 / ING-AO- 抗氧
实验（EXP-）：EXP-RHE- 流变 / EXP-TEN- 拉力 / EXP-ADH- 持粘
设备（EQ-）：EQ-RX- 反应釜 / EQ-MTR- 电机 / EQ-GRN- 造粒机
业务系统：ERP · MES · CRM + FRM · PCM · QAS（6 套系统，跨表数据闭环）

本 POC 以「员工 vibe working 副驾驶」为定位：AI 是员工的辅助工具、不对终端客户直接交互，由员工制作 / 决策后自行投放。

1.2 业务现状与九类痛点

从配方研发到文档检索，星途热熔胶在日常经营中面临九类反复出现的痛点。它们共同的特征是：数据散落在六个系统、人工逐业务巡查、频繁登录切换、时效差、易遗漏、缺乏风险预警与闭环。

第二章　九大场景的 AI 解决方案

九个场景都用同一种终端任务方式：业务用户用自己的归口账号登录终端，新建一个任务、选好模型（glm-5.2）、绑定预配置的模板智能体、粘贴一段很简短的提示词（写明"要做什么 + 针对哪些对象"）即可运行。智能体会自己判断该调用哪些业务系统、按什么顺序查，跨系统把数据凑齐，边算边输出结构化结果。用户提示词之所以能写得很短，是因为"输出格式、业务名词字典、智能体的人设与规则"这些已由平台和模板预先配好，用户只补"本次目标"即可。

📖 名词速查（看不懂的术语先看这里）
配方（FORM-）：FORM-STD- 标准品 / FORM-CUS- 定制配方，FORM-CUS-002 医疗低温热熔胶。
组分（ING-）：原料组分编号，ING-RES- 树脂 / ING-TK- 增粘 / ING-WAX- 蜡 / ING-AO- 抗氧。
实验（EXP-）：EXP-RHE- 流变 / EXP-TEN- 拉力 / EXP-ADH- 持粘；性能预测 PERF-；样品 SMP-。
工艺参数（PP-）：PP-STIR- 搅拌 / PP-REACT- 反应 / PP-COOL- 冷却，formula_no 关联配方。
设备（EQ-）：EQ-RX- 反应釜 / EQ-MTR- 电机 / EQ-GRN- 造粒机，line 关联产线 LINE-。
检测报告（QR-）：QR-IN- 来料 / QR-FG- 成品，batch_no 关联 MES 批次 BAT-。
客诉（CC-）：售后粘接故障——开胶/拉丝/堵枪/低温失效，customer_code 关联 CRM 客户 CLI-。
归口部门：负责某项业务的部门，每个场景由一个归口部门用自己的账号去跑。
vibe working：AI 作员工的副驾驶辅助日常工作，不对终端客户直接交互。
RAG：检索增强生成——让 AI 先在企业知识库检索相关内容、再据此作答。
本体 identifiers：业务"字典"，告诉 AI 每个编码是什么、跨系统怎么映射（防 404）。
技能（skill）：把一组业务系统端点打包成"功能工具"，智能体引用即用。
作用域（scope）：资源可见范围，按 组织→部门→团队→用户 逐级限定。
glm-5.2：本 POC 使用的大模型（智谱出品），终端下拉直接列真实模型 id。

第三章　AI 底座管理端配置

前两章是业务用户在终端的体验，本章是管理员（admin）在管理端为组织做的配置。管理员可管理本组织的组织架构、API Key、安全规则、智能体、工具等资源，但不能管理管理员账号、不可删除/降级自己。管理端由组织管理 / 模型路由器 / 智能体平台 / 工具连接器 / 应用监控台五大组件构成，以下逐页说明（截图均为星途热熔胶组织实测）。

3.1 平台总览与四组件

3.7 分级 scope 安全模型

平台按 组织 → 部门 → 团队 → 用户 四级 scope 限定资源可见性。组织级资源（本体、数据接口目录、DLP 规则、组织级 RAG）全员可见；部门级资源（技能、部门级 RAG、智能体）仅本部门可见；团队级资源（团队 API Key、工作空间）仅本团队可见；用户级资源（长期记忆、个人工作空间）仅本人可见。终端任务勾选归口部门技能后，智能体只暴露 bound 端点对应的工具，自然实现部门级数据可见性边界——例如研发中心的归口用户只能调 FRM+ERP 端点，看不到品质与技术服务部的 QAS 售后数据，亦看不到综合管理部的 ERP/MES 经营汇总口径。

跨系统 no-guessing 防护

每域 identifiers.md 写明编码前缀与跨码空间映射规则，智能体跨系统调用时按字段跳转而非直传异构编码，杜绝 404：组分 ING-RES-001↔采购物料 M-RES-001（prefix 转换）、配方 FORM-STD-001↔成品胶 M-FG-001（按 product_code）、定制配方 FORM-CUS-001↔生产批次 BAT-2026-0703（按 formula_no）、客诉 CC-2026-001.customer_code↔客户 CLI-001、发票 INV202607001↔凭证 BV-HMA-2026-0701（按 invoice_no）、合同 CT-HMA-001↔生产成本 PC-HMA-202607001（按 work_order_no）。
