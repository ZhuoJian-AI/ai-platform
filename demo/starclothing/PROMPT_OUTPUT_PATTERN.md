# Prompt「输出要求」段标准写法

> 抽自 PD-1 / PD-2 / PD-3 三场景验证过的稳定模式。
> 没这段，agent 在不同轮次会随机把分析内容全塞进 `.docx`，导致 ChatView 屏幕只显示一句"现在生成报告文档"，看不到 4 段分析。

---

## 问题背景

glm-5.2 在 craft 模式下，遇到任务有"生成报告"暗示时，**有时会跳过 text 流式输出**，直接调 `generate_docx` 工具把全部内容打包成附件。前端 ChatView 只渲染 `text` 事件，所以屏幕看不到分析过程。

实测过的不达标情况：

| 场景 | 不达标轮次 | text 字符数 | 现象 |
|---|---|---|---|
| PD-1 v4 | 跑 1 次失败 | 356 | 4 段分析只到 1 段 |
| PD-2 v5 | 跑 1 次失败 | 1572 | 4 段分析只到 2 段 |
| PD-3 v1 | 跑 1 次失败 | 806 | 4 段分析完全没上屏 |

加了"输出要求"段后的稳定性：

| 场景 | 修复轮次 | text 字符数 | 状态 |
|---|---|---|---|
| PD-1 v5 / v6 | 跑 2 次成功 | 4517 / 7406 | 稳定达标 |
| PD-2 v6 | 跑 1 次成功 | 7923 | 稳定达标 |
| PD-3 v2 / v3 | 跑 2 次成功 | 7334 / 8457 | 稳定达标 |

---

## 标准模板（直接复制到 prompt 末尾，"输出格式"段之前）

```
## 输出要求
**先在文本里流式输出完整分析**（<N> 段：<段1名> / <段2名> / ...，每段都有具体数据），
让评审会参与者能实时看到推理过程；**分析完成后再调 `generate_docx` 把同样内容
打包成附件**供会后归档分发。不要直接跳到 docx 生成而让 ChatView 屏幕只显示
一句"现在生成完整报告文档"。
```

`<N>` 替换为本场景的段数，`<段1名>` 等替换为该场景「输出格式」段定义的段名。

```
## 输出要求
```


---

## 为什么这段有效

1. **显式声明"先 text 后 docx"**：把顺序约束明确写出来，glm 不再随机选路径。
2. **点名段数 + 段名**：agent 必须按列表写完每一段才算"分析完成"，避免偷懒。
3. **"评审会参与者能实时看到推理过程"**：给 agent 一个角色场景理由——演示场景必须实时，不只是事后归档。
4. **"不要直接跳到 docx 生成"**：负面指令比正面指令更管用，明确禁止 agent 走的捷径。
5. **"ChatView 屏幕只显示一句..."**：给 agent 描绘不达标的失败画面，让它自我规避。

---

## 在 prompt 中的位置

```
## 执行步骤
1. ... (调端点拿数据)
2. ...
3. ...
4. 不要臆造数据，所有 X/Y 必须来自接口返回。

## 输出要求  ← 加在这里
**先在文本里流式输出完整分析**...

## 输出格式
(1) <段1名>：列1 | 列2 | ...
(2) <段2名>：...
```

顺序：执行步骤 → 输出要求 → 输出格式。"输出要求"是行为约束，"输出格式"是结构规范。

---

## 段数计算

参考各场景「输出格式」段定义的 `(1) (2) (3) (4)` 编号——有几个就是几段：

- PD-1：(1) 全流程进度汇总表 (2) 逾期款号推送清单 → 2 段
- PD-2：(1) 面料对比汇总表 (2) 选用建议清单 (3) 异动预警 → 3 段
- PD-3：(1) 风险预警表 (2) 评审必查项 (3) 闭环验证建议 (4) 闭环待办 → 4 段

新场景按你「输出格式」段的编号数填即可。

## 验证方法

跑完任务后用 SSE 解析检查 text 事件字符数：

```bash
python3 -c "
import json
events = []
with open('/tmp/<run>.sse') as f:
    for line in f:
        line = line.strip()
        if line.startswith('data: '):
            try: events.append(json.loads(line[6:]))
            except: pass
text = ''.join(e.get('delta','') for e in events if e.get('type')=='text')
print(f'text chars: {len(text)}')
for marker in ['段1关键字', '段2关键字', ...]:
    print(f'  {\"✓\" if marker in text else \"✗\"} {marker}')
"
```

**达标线**：text ≥ 3000 字符，每段关键字都命中（"对比"/"建议"/"预警"/"待办" 等）。

**未达标处理**：
- 检查 prompt 是否真的有「## 输出要求」段
- 检查段数 / 段名是否对得上「## 输出格式」段
- 重跑一次（glm 仍有 ~10% 概率走捷径，跑 2 次都失败说明 prompt 写错了）

---

## 反例：不要这样写

❌ **缺"输出要求"段**：agent 会随机走捷径，演示前不可控。

❌ **"输出要求"放在"输出格式"之后**：agent 先看到结构再看到约束，约束效力减半。

❌ **只写"先 text 后 docx"不写段名**：agent 会偷懒只写 1~2 段就跳到 docx。

❌ **不写"不要直接跳到 docx"负面指令**：正面指令约束力弱，负面指令才能堵死捷径。
